# GameBoardの低速回線再現

下り5.2 Mbpsで初回に画像を表示する状況を、Chromiumで繰り返し確認できます。
アプリの動作や通常のE2Eの速度・タイムアウトは変更しません。

```sh
npm run test:e2e:slow-network
```

本番ビルドを作成し、専用のローカルプレビュー（4176番ポート）で次の2条件を実行します。

| 条件 | 画像の合計下り帯域 | 追加の応答遅延 | キャッシュ |
| --- | --- | --- | --- |
| 帯域のみ | 5.2 Mbps = 650,000 bytes/秒 | 0ms | 無効 |
| 帯域と遅延 | 5.2 Mbps = 650,000 bytes/秒 | 150ms | 無効 |

速度制限は画像配信用のローカルHTTPサーバーにだけ適用します。個々の画像に5.2 Mbpsを
割り当てるのではなく、同時リクエスト全体で帯域を共有します。アップロード・CPU・
パケット損失は制限しません。HTTP/1.1のローカル画像サーバーを使い、実機間WebRTC通信や
公開サイト側の通信方式・DNS/TLS・配信元の混雑は再現しません。

約620KBの有効なPNGをメモリー上で生成し、HTTPで実際に転送します。
小さい画像に固定の待ち時間を加える方式ではありません。画像ファイルのGit管理や
外部画像サービスへのアクセスは不要です。カード一覧・詳細は小さい検証用データに
置き換え、JavaScript・カタログ取得の遅さと画像転送の遅さを分離します。

## 確認する内容

- 制限前後に同サイズの画像を取得し、制限が実際に効いていることを校正する。
- 画像取得中でも、デッキ内の全40枚を選択・選択解除できる。
- 画面付近の画像が表示され、最終行へスクロールした際も画像が表示される。
- 40枚の画像を初回に一斉取得せず、デッキの枚数・構成を変えない。

結果は `test-results/slow-network/` の各ケース内の `measurements.json` と
`trace.zip`、およびPlaywrightのHTMLレポートに残ります。レポートには制限前後の転送時間、
初回の先頭画像表示時間、初回の画像要求数、画像ごとの応答開始・取得時間とサイズを記録します。
数値は検証環境の結果であり、公開サイトやゲスト端末での実測値とは区別してください。

```sh
npx playwright show-report
# ビルド後、動作をブラウザーで見たい場合
npx playwright test --config playwright.slow-network.config.ts --headed
```

通常の `npm run test:e2e` と本番E2Eには、この時間のかかる検証を追加しません。
所有するテストは `e2e/slow-network/game-board-artwork.spec.ts` です。

公開サイトでも確認したい場合は、Chromiumの開発者ツールのNetworkでキャッシュを無効にし、
カスタム速度を下り5,200 kbit/秒、必要に応じて遅延150msにして再読み込みします。
こちらはサイトのHTTPリクエスト全体が対象となるため、画像だけを制限する自動テストとは
適用範囲が異なります。テスト後は通信制限を解除してください。

## ローカルでの測定例

620,567 bytesの画像を使った測定例です。

| 条件 | 制限なしの1枚取得 | 制限ありの1枚取得 | デッキ一覧の先頭画像表示 | 初回要求数 |
| --- | --- | --- | --- | --- |
| 5.2 Mbps・0ms | 約6ms | 約967ms | 約6.1秒 | 12種類 |
| 5.2 Mbps・150ms | 約4ms | 約1,127ms | 約6.2秒 | 12種類 |

150msの条件では、JavaScriptが応答ヘッダーを受け取るまで約152msかかったことも校正しています。
画像ごとのResourceTimingに加え、制限前後のfetchで測った経過時間を併記します。
一覧の表示時間は同時取得やUIの確認タイミングで変動するため、2ケースの小さな差を
性能差と判断しないでください。これは公開サイトでの実測値ではありません。
