# GameBoard のポインター操作と E2E

## 調査で確認した原因

- 既定の PointerSensor は押下時に即座にドラッグを開始していた。
  カードをクリックしただけでもドラッグとして扱われ、現在使用している dnd-kit の
  `AbstractPointerSensor.detach` が終了後50ms保持する document のクリック抑止が働いていた。
  詳細を開いた直後の「閉じる」など、次のクリックが届かない原因になっていた。
- ドラッグ中に開始位置へ戻して離すと、カード側の移動量判定だけではタップと判断できてしまった。
- E2E のカード中央からのドラッグは、ホバーで出現する操作ボタンと重なることがあった。
  また、つかんだ位置を考慮せずカーソルを移動先の中央へ置くと、カード自体の中心はずれ、
  重なった別のカードが移動先として判定されることがあった。
- 移動先の判定前にマウスを離す操作や、実ドラッグ終了直後のクリックも不安定性の原因だった。

## アプリ側の修正

- GameBoard の PointerSensor は6pxを超える移動で開始する。静止した押下や小さなぶれはドラッグにしない。
- KeyboardSensor は既定の設定を明示して維持する。
- Card はドラッグ中の pointer-up を詳細表示・タップ操作として処理しない。
  ドラッグ開始時にタップ候補も解除し、Escape でキャンセルした後の pointer-up もタップと誤認しない。
  ドラッグ開始前の押下も Escape で解除する。いずれも次の意図したタップは有効なままにする。
- カードの移動規則、禁止移動、Undo の履歴処理には変更を加えていない。

## E2E 側の操作

`e2e/helpers/gameBoard.ts` に操作を集約する。
ボタンや他のカードに覆われていない位置をホバー後に取り直し、移動してドラッグを開始する。
ドラッグ中のカードと移動先の現在の矩形から中心の差を計算する。
途中でスクロールして移動先がずれた場合も矩形を取り直して補正し、移動先の通知を確認してから一度だけ離す。
初期座標を使い続けて別のゾーンに留まる競合を防ぐ。待機期限は従来と同じ5秒で、期待する移動先は緩和しない。

キーボードドラッグは `startKeyboardCardDrag` を使う。dnd-kitのKeyboardSensorは開始の描画後、
別のタスクでdocumentのキーリスナーを登録する。`aria-pressed` や開始直後の移動通知だけでは登録完了を示さない。
実際の右矢印キーでカードのtransformが変わることを確認してからUndo・Escapeを送る。
固定時間の待機やEscapeの再送で成功扱いにせず、キー受付を確認した後の取消とUndoを従来どおり検証する。

カードを明示したドロップでは、そのカードのIDを確認する。
ゾーンを指定したドロップでは、ゾーン本体またはその中に既にあるカードが移動先になり得る。
これはアプリが移動先カードのゾーンを解決する既存仕様に合わせた確認である。
移動後の枚数や禁止移動、Undo の期待値は各フローテストで引き続き検証する。

実ドラッグ終了後の50ms待機は、dnd-kit のクリック抑止が解除されるまでの待機であり、
アプリ側に追加した遅延ではない。この解除にはDOM上の完了通知がないため、補助関数内で明示的に待つ。
依存ライブラリを更新するときは、この待機の必要性と期間も再確認する。

## テスト所有先

- `e2e/game-board-drag-synchronization.spec.ts`: ドラッグ途中の180pxスクロール、キー受付の遅延を意図的に発生させ、操作ヘルパーの待機と移動・取消・Undoを検証。
- `e2e/solo-pointer-interactions.spec.ts`: 静止した押下、小さなぶれ、ドラッグ開始、元の位置で離す操作、キャンセル後に離す操作、詳細を閉じる操作。
- `src/components/Card.test.tsx`: ドラッグ後に詳細表示を誤って開かない契約。
- `e2e/solo-board-movement.spec.ts`: ゾーン間移動と禁止されたデッキ混在の拒否。
- `e2e/solo-token-stack.spec.ts`: トークンの消滅、重ねたカードの移動とUndo。
- `e2e/solo-multi-selection.spec.ts`・`e2e/solo-undo-shortcut.spec.ts`: 重ねたカードの選択とキーボード操作の回帰確認。

実ブラウザーの座標・ドラッグ開始判定は Chromium E2E で検証する。
Safari・実機タッチの細かい操作感は、この自動テストでは保証しない。
