# 詳細グループの再分割形式（schema 3）

この段階ではReaderだけがschema 3に対応します。通常のPython生成・開発サーバー・本番ビルドはschema 2のままです。
実配信への切り替えは、生成器の対応と生成物検証を別の変更で実施してから判断します。

## 形式と互換性

manifestは`schemaVersion: 3`を使用します。indexはschema 2と同じ`rows-v1`形式、同じ20列の固定ヘッダーと存在ビットマスクです。
詳細JSONは引き続き全項目を保持したカード配列です。カードID・配列順・省略項目・関連カード・保存デッキ・通信形式を変更しません。
Readerはschema 1（オブジェクト配列index）とschema 2も引き続き検証して読み取ります。未対応のバージョンは拒否します。

グループ名は、カードIDの最初の`-`より前の部分を商品プレフィックスとして、商品ごとに次のいずれかを使用します。

- 未分割: `BP01`
- 分割: `BP01@0001`, `BP01@0002`, …（1から欠番なく連番）

プレフィックスは英数字とアンダースコアのみです。番号は最低4桁とし、10000以降も桁を切らずに続けます。
0・余分な先頭0・パス区切り・URLエンコードした区切りは拒否します。
同じ商品で未分割名と分割名を混在させません。異なる商品は分割・未分割が混在できます。
`@0001`だけの表現もReaderは受け入れます。生成器側では、分割が不要な商品は未分割名を維持する予定です。
schema 1・2では`@`を含むグループを引き続き拒否します。

各index行の`detail_group`はmanifestに存在する正確なグループIDを参照し、その商品プレフィックスはカードIDと一致する必要があります。
商品フィルターは従来どおりカードID・既存メタデータを使用し、分割番号を商品として扱いません。

## 検証と取得

詳細の参照先は`versions/<catalogVersion>/details/<group>.json`です。
manifestのバージョン計算は既存と同じ正規化JSON＋末尾改行のSHA-256で、`schemaVersion: 3`と全ファイルのハッシュを含みます。
各ファイルのサイズ・SHA-256・UTF-8、件数、カード項目、indexの完全な射影、関連カード参照を検証します。
詳細カードはindexで割り当てられたグループに完全一致する必要があり、同じ商品内でも別の分割ファイルへの混入を拒否します。
分割ファイル間でindex割当件数を移した改変も拒否します。

既存の取得キュー・Promise共有・キャッシュをそのまま使用します。1カタログ最大4件の詳細取得、本文受信を含む30秒のタイムアウト、失敗グループだけの再試行を維持します。
GameBoardの候補カタログ切り替えも、必要な詳細の検証完了後に実施する既存の処理を使用します。

新Readerは旧形式を読めますが、旧Readerはschema 3を読めません。将来の配信切り替え時に以前から開いている画面では再読み込みが必要になる場合があります。
旧生成物をGitに蓄積する運用は追加しません。

## 検証の所有先と次の段階

- Reader契約: `src/utils/card/generatedCardCatalog.test.ts`（正確な所属、不正参照、旧形式、順序・重複、関連カード、キュー、失敗・再試行）
- index形式: `src/utils/card/generatedCardIndex.test.ts`（schema 2・3の同一展開と厳格な不正形式拒否）
- 実データ: `src/utils/card/generatedCardCatalogParity.test.ts`（通常生成のschema 2と、比較モデルからテスト用に再包装したschema 3の全カード一致）
- ブラウザー: `e2e/game-board-generated-recovery.spec.ts`（旧sourceからschema 2・3への復旧とプレイ中の維持）
- 本番バンドル: `e2e/production/catalog-request-limit.spec.ts`（両形式で同時取得4件と全カード表示）

次は生成器と`--check`をschema 3に対応させます。初期候補は元の詳細が384 KiBを超えた商品のみを128 KiB目標で分割する方針です。
この閾値は生成方針であり、Readerの形式制約にはしません。単独で上限を超えるカードは分解せず保持する予定です。
生成器対応後、全件一致・決定性・ビルド生成物・実データE2E・Vercel Previewでリクエスト数と転送量を確認してから配信を切り替えます。
